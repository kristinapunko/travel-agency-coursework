# План проєкту: Веб-сайт автоматизації управління роботою турагентства

## 1. Тема та проблема предметної області

**Тема проєкту:**
**«Веб-сайт автоматизації управління роботою турагентства» (Тема №33).**

### Актуальність проєкту

Сучасний туристичний бізнес потребує швидкого та зручного обслуговування клієнтів. Традиційний процес підбору туру часто передбачає тривале листування або телефонні розмови з менеджером турагентства. Клієнту необхідно уточнювати актуальні пропозиції, ціни, наявність місць, умови поїздки та лише після цього оформлювати заявку.

Такий підхід має низку недоліків:

* значні витрати часу на комунікацію між клієнтом і менеджером;
* збільшення навантаження на працівників турагентства;
* ризик втрати потенційних клієнтів через тривале очікування відповіді;
* складність оперативного контролю актуальних бронювань;
* необхідність ручного опрацювання великої кількості однотипних заявок.

### Запропоноване рішення

Для вирішення зазначених проблем пропонується розробити **вебзастосунок для автоматизації роботи турагентства**.

Система дозволить клієнтам самостійно переглядати доступні туристичні пропозиції, ознайомлюватися з їх характеристиками, обирати потрібний тур та оформлювати бронювання онлайн.

Для працівників турагентства система передбачатиме можливість перегляду та опрацювання заявок, зміни їх статусів і контролю актуальності туристичних пропозицій.

Таким чином, вебзастосунок має скоротити кількість ручних операцій, пришвидшити обслуговування клієнтів та зробити процес бронювання більш зручним і прозорим.

# 2. Сутності предметної області

Основними сутностями системи є **тури, бронювання та відгуки**.

## 2.1. Тур (Tour)

Сутність **Tour** описує туристичну пропозицію, доступну для перегляду та бронювання.

Основні атрибути:

| Атрибут       | Опис                                                                 |
| ------------- | -------------------------------------------------------------------- |
| `id`          | Унікальний стабільний ідентифікатор туру                             |
| `name`        | Назва туристичної пропозиції                                         |
| `country`     | Країна або напрямок подорожі                                         |
| `duration`    | Тривалість подорожі в днях / ночах                                   |
| `price`       | Вартість туру в USD або UAH                                          |
| `description` | Короткий опис програми та особливостей туру                          |
| `category`    | Категорія відпочинку: пляжний, екскурсійний, гірський, сімейний тощо |
| `isAvailable` | Поточний стан доступності місць                                      |

Поле `isAvailable` дає змогу визначити, чи може користувач оформити бронювання конкретного туру.

## 2.2. Бронювання (Booking)

Сутність **Booking** представляє заявку клієнта на придбання туристичної послуги.

Основні атрибути:

| Атрибут          | Опис                              |
| ---------------- | --------------------------------- |
| `id`             | Унікальний номер бронювання       |
| `tourId`         | Ідентифікатор пов'язаного туру    |
| `customerName`   | Ім'я та прізвище контактної особи |
| `customerEmail`  | Електронна пошта клієнта          |
| `customerPhone`  | Номер телефону клієнта            |
| `travelersCount` | Кількість туристів                |
| `totalPrice`     | Загальна розрахована вартість     |
| `status`         | Поточний стан заявки              |

Для `status` передбачаються такі значення:

* **pending** — заявка створена та очікує опрацювання;
* **confirmed** — бронювання підтверджено;
* **paid** — виконано оплату;
* **cancelled** — бронювання скасовано.

## 2.3. Відгук (Review)

Сутність **Review** використовується для зберігання оцінок та вражень клієнтів після подорожі.

Основні атрибути:

| Атрибут   | Опис                                        |
| --------- | ------------------------------------------- |
| `id`      | Унікальний ідентифікатор відгуку            |
| `tourId`  | Ідентифікатор туру, якого стосується відгук |
| `author`  | Автор відгуку                               |
| `rating`  | Оцінка туру від 1 до 5                      |
| `comment` | Текстове враження клієнта                   |

Зв'язок `tourId` забезпечує прив'язку бронювань та відгуків до конкретної туристичної пропозиції.

# 3. Групи користувачів та їхні сценарії

У системі передбачено три основні групи користувачів.

| Група                     | Основна потреба                        | Основний сценарій                                    |
| ------------------------- | -------------------------------------- | ---------------------------------------------------- |
| **Відвідувач**            | Підібрати тур та ознайомитися з цінами | Перегляд і порівняння туристичних пропозицій         |
| **Покупець**              | Оформити подорож онлайн                | Вибір туру, заповнення форми та створення бронювання |
| **Менеджер турагентства** | Автоматизувати роботу із заявками      | Перегляд бронювань, зміна статусів та контроль турів |

## Сценарій 1. Перегляд доступних турів

**Користувач:** Відвідувач.

**Передумова:** вебзастосунок відкрито у браузері.

Послідовність дій:

1. Користувач переходить до секції каталогу через навігаційне меню.
2. Система відображає доступні туристичні пропозиції.
3. Користувач переглядає картки турів.
4. У картці відображаються назва, країна, тривалість, ціна та інформація про доступність.
5. Користувач ознайомлюється з коротким описом програми подорожі.
6. На основі отриманої інформації користувач обирає тур, який відповідає його потребам.

**Результат:** користувач визначився з туристичною пропозицією для подальшого перегляду або бронювання.

**Альтернативний сценарій:** якщо каталог не містить доступних турів, система відображає зрозуміле інформаційне повідомлення про відсутність актуальних пропозицій.

**Стан реалізації:** реалізовано в межах **Л 1.1**.

---

## Сценарій 2. Оформлення бронювання

**Користувач:** Покупець.

**Передумова:** користувач вибрав конкретний тур, для якого доступні місця.

Послідовність дій:

1. Користувач відкриває сторінку детальної інформації про тур.
2. Натискає кнопку переходу до бронювання.
3. Система відкриває форму замовлення.
4. Користувач вводить ім'я, номер телефону, електронну пошту та кількість туристів.
5. Система перевіряє коректність введених даних.
6. На основі ціни туру та кількості туристів система розраховує загальну вартість.
7. Користувач підтверджує заявку або переходить до тестового етапу оплати.
8. Система створює об'єкт `Booking` зі статусом **pending**.
9. Користувач отримує повідомлення про успішне створення заявки.

**Результат:** бронювання успішно створене та передане на подальше опрацювання.

**Альтернативний сценарій:** якщо користувач допустив помилку під час заповнення форми, система показує відповідні підказки та повідомлення про помилки, не видаляючи вже введені дані.

**Стан реалізації:** заплановано на наступні етапи розробки.
